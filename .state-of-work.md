## Key Decisions
- **React Native + Expo (SDK 57)** chosen over Flutter — user's existing familiarity, confirmed via AskUserQuestion.
- **react-native-mmkv with synchronous writes** for all local persistence (session state, segments, history) — resolves the PRD's flagged "riskiest assumption" (async-write/<100ms split) more simply than originally anticipated. Requires `expo-dev-client`, not plain Expo Go, since MMKV is a native module.
- **`target_streak` is derived on every read**, never persisted as its own field — only `current_streak`, `total_incorrect_this_session`, `segment_name`, `session_start_timestamp`, `session_complete` are persisted.
- **No SQLite, no Redux/Zustand** — MMKV JSON collections + React Context/hooks (`useActiveSession`) cover the app's full state surface given its small scope.
- **No added component library (no React Native Paper)** — standard screens use RN's own built-in components (`Pressable`, `Modal`, `FlatList`, `TextInput`), manually configured for accessibility. This was a mid-session clarification fixing an ambiguity between the UX spec and architecture doc.
- **3 epics, not 5** — Session Lifecycle, Active Session Interaction, and Interruption & Recovery were consolidated into one epic ("The Overlearning Session") because they share the same core files and none is independently meaningful alone.
- Screen-reader announcements use React Native's built-in `AccessibilityInfo.announceForAccessibility()` — no new dependency.
- Story 2.9 was retitled from "Persist Full Session State..." to "Verify Interruption Survival..." mid-readiness-check to fix a forward-dependency ambiguity — the actual MMKV plumbing is established starting in Story 2.1, not introduced late.
