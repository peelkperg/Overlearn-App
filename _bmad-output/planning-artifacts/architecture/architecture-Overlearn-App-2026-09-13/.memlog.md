- (decision) Base path: GitHub Pages subpath (/Overlearn-App/ or repo slug), not a custom domain, for now. Binds router base URL, PWA manifest start_url/scope, and service worker registration scope to the same subpath. Prevents: three independently-configured base paths drifting apart. Revisit if a custom domain is attached later (root-path everywhere, same three sites to update).
- (decision) Service worker precache generation: Workbox (workbox-build's generateSW) as a postbuild step after expo export, not hand-rolled. Binds: PWA offline-shell task. Prevents: hand-rolled cache-versioning/activate-eviction bugs (stale index.html referencing a since-removed hashed bundle after a redeploy — the classic PWA footgun). Cleared against dependency governance: Google-maintained, MIT, active release cadence, build-time-only devDependency, no runtime attack surface added. Condition: pin exact version in package.json, no floating range. Decided via code-review-crew party debate 2026-09-13.
- (constraint) Dynamic routes (segment/[id], segment/[id]/rename, session/[id]) have ids created locally at runtime (user's own data), unknowable at build time -- confirmed by reading src/app/**. These cannot be statically prerendered per-route; they resolve client-side against local storage after the app shell loads. Binds: static export + GitHub Pages deploy + SPA-routing fallback. Prevents: assuming Expo Router's static output covers these routes, and skipping the 404-to-index.html rewrite as optional -- it is required, not conditional, for any deep link/reload past the root route.
- (decision) Deploy mechanism: GitHub's native Pages deployment (actions/upload-pages-artifact + actions/deploy-pages), not a gh-pages-branch push via a third-party action. Binds: .github/workflows/deploy-pages.yml. Prevents: an extra branch to reason about and a third-party action in the trust chain when a first-party equivalent exists.
- (decision) [ADOPTED from spec] Storage: web platform backs storage.ts's existing public API with a Platform.OS==='web' branch constructing a localStorage-backed raw store; everything above the raw store (getObject/setObject, migrate, quarantine) is unchanged and platform-agnostic. Binds: src/lib/storage.ts. Prevents: a parallel/divergent storage implementation for web; call sites above the boundary never change.
- (decision) [ADOPTED from spec] subscribeToKeys notification: an in-module listener Set fired synchronously on every set/remove (matching MMKV's same-process semantics), with a MMKV-shaped .remove()-bearing handle for unsubscribe and per-listener try/catch isolation so one throwing subscriber cannot block siblings or the write path. Binds: src/lib/storage.ts web branch.
- (decision) Service worker update lifecycle: use Workbox generateSW's own default (no skipWaiting/clientsClaim) -- a newly deployed SW activates only once all tabs of the old version are closed, never displacing assets under an in-progress session. Binds: public/service-worker.js registration. Prevents: a mid-session asset swap while a practice session is active. Follows directly from the Workbox decision (AD above); not separately elicited since it is Workbox's documented default and matches the app's no-hidden-mutation posture.
