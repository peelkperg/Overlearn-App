- (decision) Audio capture: expo-audio (Expo SDK 57's current-generation audio module), not the deprecated expo-av Audio API. Binds: microphone recording for template capture (CAP-3) and live listening windows (CAP-1). Prevents: shipping a known-deprecated Expo dependency. User-confirmed 2026-09-16.
- (decision) MFCC extraction and DTW distance: hand-rolled pure TypeScript (no new npm dependency), per stack.md's DTW-over-MFCC choice. Binds: src/lib/voiceCommand/mfcc.ts, dtw.ts. Prevents: a dependency-governance approval (CLAUDE.md §5.2) for a one-off, well-bounded algorithm over three short templates; avoids meyda (Web Audio API-targeted, poor RN fit). User-confirmed 2026-09-16.
- (decision) Listening lifecycle: mic capture runs only while the Active Session screen is mounted AND the mic toggle is on. Backgrounding the app or navigating away stops capture immediately; no background audio capability or foreground service is added. Binds: useVoiceCommand hook lifecycle (mount/unmount, AppState). Prevents: background-audio entitlement/foreground-service complexity for an inherently foreground, hands-busy-at-the-instrument feature. User-confirmed 2026-09-16.
- (decision) Trigger template storage: only the extracted MFCC feature matrix per trigger (wake, Correct, Incorrect) is persisted to MMKV — never the raw recorded audio buffer. Binds: a new lib/voiceTriggers.ts storage module. Prevents: an indefinitely-retained raw voice recording on disk; keeps MMKV payloads to a few KB. Matches NFR8's device-only-data posture more conservatively than required. User-confirmed 2026-09-16.
- (decision) Matcher calls the existing tap-path transitions directly (the same logCorrect/logIncorrect functions the Correct/Incorrect buttons call in useActiveSession), not a parallel voice-specific write path. Binds: src/lib/voiceCommand/matcher.ts -> useActiveSession's existing handlers. Prevents: a second session-state mutation path that could drift from the tap path's MMKV write strategy, streak/target logic, or completion transition (directly required by SPEC's success signal: voice-only session counters must match tap-only).
- (constraint) Mic OS permission is requested lazily via expo-audio's permission API, only on the first mic-toggle-on — never at install/onboarding/app launch. Binds: the mic toggle's onPress handler. Matches SPEC-voice-command-input's stated constraint; a permission-denied response leaves the toggle off with an inline explanation, no retry loop.
- (decision) Wake-gating is a two-state matcher: LISTENING_FOR_WAKE (checks only the wake template) and AWAITING_COMMAND (checks only Correct/Incorrect templates, for a bounded window after a wake match, then reverts to LISTENING_FOR_WAKE on timeout with no action taken). Binds: src/lib/voiceCommand/matcher.ts state machine. Prevents: an ungated matcher that could fire Correct/Incorrect from ambient noise resembling those templates in isolation (SPEC constraint). The exact timeout duration is left to story-level tuning, not fixed here — a real number needs empirical tuning against recorded fixtures, not an architectural invariant.
- (decision) CAP-3's distinguishability check reuses the same dtw.ts distance function as live matching, computed pairwise across the three saved templates' MFCC matrices; a pair below the separation threshold blocks save. Binds: the trigger-recording save flow (voiceTriggers.ts). Prevents: a second, divergent similarity metric between save-time validation and run-time matching.
