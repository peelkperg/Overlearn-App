## Intent

**Problem:** Epic 6 needs `storage.ts` to work correctly on web. Investigation before writing any code found `react-native-mmkv@4.3.2` (already the pinned version) ships its own `createMMKV.web.ts`, which Metro's platform-file resolution automatically substitutes for web bundles — a complete `localStorage`-backed implementation covering construction and every raw-store method `storage.ts` uses, already firing `subscribeToKeys` listeners synchronously from an in-module `Set`. Verified empirically: `npx expo export --platform web` against the real, unmodified `storage.ts` built clean, and the bundle contains the web module's `mmkv.default` key prefix and `getLocalStorage`, proving Metro picked the real implementation, not a crash path. **Decision (2026-09-14, human-confirmed):** no `Platform.OS` branch or hand-rolled adapter is added — that would duplicate working dependency behavior. `ARCHITECTURE-SPINE.md` AD-1/AD-2 amended to match. This story becomes verification: prove the existing contract holds through the dependency's web build, and close the one gap investigation found unverified — the dependency's listener fan-out (`listeners.forEach((l) => l(key))`) has no per-callback try/catch, so per-listener error isolation may not hold as `subscribeToKeys`'s existing callers assume.

**Approach:** Add a parallel web-path `describe` block to `storage.test.ts` — no change to `storage.ts` itself — exercising `getObject`/`setObject`/`subscribeToKeys`/quarantine/migration against the dependency's real web implementation. Get web-path tests running under Jest by mocking `Platform.OS` to `'web'` and using `jest.resetModules()` + a fresh `require('./storage')` inside the web `describe` block (isolated from the native describe blocks' already-imported instance, which stays on the default platform) — no `jest.config.js`/preset change, no jsdom (the dependency's own `getLocalStorage()` helper already degrades safely when `window`/`localStorage` isn't available, matching this project's Node test environment). Test the per-listener error-isolation gap explicitly; if it fails, record it as a `deferred-work.md` entry against the dependency (not a defect in this codebase) rather than working around it here. Finish with a real `npx expo export --platform web` + a manual browser check (segment/session persistence across reload, cross-component `subscribeToKeys` notification) as the acceptance-level confirmation, per Epic 6's Story 6.1 ACs in `epics.md` (those ACs describe required behavior and hold regardless of whether it comes from new code or the dependency's existing code).

## Implementation Notes

- **2026-09-14 — stopped before implementing, replanned.** Investigation before writing code found `react-native-mmkv@4.3.2` already provides full web support via Metro's platform-file resolution — see Intent above for the empirical verification. Human confirmed: verification-only scope, and amend `ARCHITECTURE-SPINE.md` AD-1/AD-2 to match (done). Resuming as a (smaller) oneshot from here.
- **Test mechanism.** Jest's own platform-file resolution (`.web.js`) is a Metro-bundler-time mechanism inactive under this project's plain `jest-expo` preset — mocking `Platform.OS` alone would not make `createMMKV` resolve to the web implementation. Used `jest.doMock('react-native-mmkv', () => require('react-native-mmkv/lib/createMMKV/createMMKV.web'))` + `jest.resetModules()` + a fresh `require('./storage')` instead, scoped to the new `describe` block; the native describe blocks' already-imported `storage` binding is unaffected (captured before any mocking, and `resetModules()` only changes future `require()` calls). No `jest.config.js` change.
- **`localStorage` shim.** No `window`/DOM at all under this project's Node test environment, so a hand-rolled `Storage`-shaped stub was needed (not jsdom — out of scope for this story). First attempt used a `Map`-backed stub and failed: the dependency's `getAllKeys()`/`clearAll()` both rely on `Object.keys(localStorage)` enumerating stored entries as the object's own enumerable properties (real browser behavior) — a `Map`-backed stub doesn't expose that. Fixed via `Object.create(proto)`: methods live on the prototype (excluded from `Object.keys()` on the instance), `setItem`/`removeItem` assign/delete directly on `this` so stored entries become genuine own enumerable properties, matching real `localStorage` semantics exactly.
- **Two real defects found and patched** (both proven first by a failing test, not assumed from reading source):
  1. `subscribeToKeys`'s listeners were never isolated from each other — neither the native nor the web `react-native-mmkv` implementation wraps individual callbacks (`Set.forEach` with no per-callback try/catch), so one throwing subscriber aborted the whole fan-out: every listener registered after it was silently skipped, **and** the throw propagated out through the `set`/`remove` call that triggered notification, meaning a bad subscriber could crash an unrelated write. Fixed by wrapping `onChange` in `subscribeToKeys` itself (platform-agnostic, one function, no new public API) — fixes both platforms uniformly.
  2. `setString`/`setNumber`/`deleteKey` had no failure guard at all (only `getString` did, from a 2026-09-05 patch). `localStorage.setItem` can genuinely throw on web (quota exceeded); nothing caught it, so a full-storage browser would crash on the very next write. Fixed by wrapping all three in try/catch, matching `getString`'s existing degrade-to-no-op pattern exactly.
- **Verification:** `npx jest storage.test.ts` — 27/27 pass (20 native unchanged + 7 new web-path). Full suite: 424/425 pass; the one failure (`SegmentListItem.test.tsx`, a 5s-timeout flake) is the pre-existing, already-documented issue in `deferred-work.md` ("test suite is timing-flaky at Jest's default 5-second timeout") — confirmed unrelated by re-running that file alone with `--testTimeout=30000` (32/32 pass). `npx tsc --noEmit` clean. `npm run lint` clean on both changed files (one pre-existing error/warning elsewhere, in files this story never touched). `npx expo export --platform web` built clean both before *and* after the code changes (1201 modules, 9 static routes).
- **Review:** subagents declined at first invocation, so the Blind Hunter prompt was written to `review-prompt-6-1-blind-hunter.md`. On resume in a fresh session, the user opted to run it as a subagent instead of pasting back a manual run — see `## Review Triage Log`.
- **Patch from review:** `setObject` (src/lib/storage.ts) called `storage.set` directly instead of `setString`, so it bypassed the degrade-to-no-op protection this story added to every other write path — the exact web quota-exceeded crash the story exists to prevent, on the app's busiest write path (every segment/history/session write). Fixed by routing through `setString`. Added a matching `storage.test.ts` case (`degrades setObject to no-op ... quota exceeded`). Re-verified: `npx jest storage.test.ts` 28/28 pass (27 prior + 1 new), `npx tsc --noEmit` clean, `npx eslint src/lib/storage.ts src/lib/storage.test.ts` clean.
