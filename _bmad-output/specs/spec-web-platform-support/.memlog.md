topic: Web platform support: storage-layer web branch, PWA installability/offline shell, GitHub Pages hosting
updated: 2026-09-14T12:45

- (decision) Why: Overlearn only runs natively on iOS/Android via react-native-mmkv (zero web support). No iOS build ships right now (Android-only native). Web/PWA reach is the way to make the app available to iOS-excluded users -- free, ad-free, no new accounts -- via GitHub Pages (repo already lives there). Source: spec-web-platform-support.md Intent + party-mode discussion 2026-09-13.
- (capability) CAP-1 Web-compatible storage layer -- intent: storage.ts backs its existing public API with a localStorage adapter on web (matching MMKV's raw-store contract exactly, including construction timing per ARCHITECTURE-SPINE AD-1), so every layer above it works unmodified. success: a segment/session/history created via a web build persists across a page reload identically to native; existing native storage tests pass unmodified; new web-path tests pass (quarantine, migration, subscribeToKeys sync notify + per-listener error isolation + unsubscribe, storage-unavailable degradation).
- (capability) CAP-2 Installable, offline-capable web app (PWA) -- intent: the web build is installable and loads its app shell with zero connectivity after first load, matching native's offline-first experience for the users this web build exists to reach. success: browser install affordance works; a deployed build with network disabled after first load still boots and functions; a direct reload on a non-root route still loads the app shell (not a 404).
- (capability) CAP-3 Free, ad-free static hosting via GitHub Pages -- intent: the web build deploys automatically to GitHub Pages on push to main via GitHub's native Pages Actions, at a repo subpath (no custom domain for now). success: pushing to main produces a live, reachable deployment at the GitHub Pages URL; a segment/session run to completion on that live URL persists across reload, matching the local-dev-server check.
- (capability) CAP-4 Durability-guarantee documentation -- intent: prd.md gets a short NFR8/9 addendum documenting the web build's weaker durability (no OS sandbox; vulnerable to browser-data clearing or profile switching) while the 'zero data leaves the device' guarantee is unchanged. success: prd.md contains the addendum.
- (constraint) storage.ts's public API/signatures unchanged for both platforms; no call site above the storage boundary may change. Quarantine convention and versioned-envelope migration chain reused as-is, no parallel implementation.
- (constraint) subscribeToKeys fires synchronously on every set/remove, per-listener error-isolated (one throwing subscriber can't block siblings or the write), with an explicit MMKV-shaped unsubscribe handle (ARCHITECTURE-SPINE AD-2).
- (constraint) Service worker precache is generated by Workbox (workbox-build, pinned exact version) from the real static-export output, covering 100% of dist/, never hand-maintained; update lifecycle uses Workbox's conservative default so an in-progress session is never swapped under itself (ARCHITECTURE-SPINE AD-5).
- (constraint) No backend, accounts, or telemetry introduced to support hosting or installability -- GitHub Pages serves static files only (ARCHITECTURE-SPINE AD-7).
- (constraint) Deploy via GitHub's native Pages Actions (actions/upload-pages-artifact + actions/deploy-pages) only, not a third-party gh-pages-branch action (ARCHITECTURE-SPINE AD-6).
- (constraint) Base path is one named config key (app.json#expo.extra.basePath) read directly by router, manifest, and service-worker registration -- never re-derived independently by each (ARCHITECTURE-SPINE AD-3, AD-8).
- (decision) Non-goal: full PWA feature surface beyond installability/offline shell (push notifications, background sync, share-target) -- no driver to add them.
- (decision) Non-goal: custom domain -- subpath deploy accepted for now, deferred.
- (decision) Non-goal: full cross-browser/UAT-equivalent audit -- this covers booting, installing, and deploying, not exhaustive polish.
- (decision) Non-goal: multi-environment (staging/preview) deploy -- single production environment only.
- (decision) Non-goal: deploy rollback procedure -- explicitly deferred, not decided; revisit before relying on this beyond solo-maintainer use.
- (decision) Success signal: a segment created and a practice session run to completion on the live GitHub Pages URL (not local dev server) persists across a reload, the app works offline after first load, is installable via the browser's affordance, and a direct reload on a non-root route loads the app shell rather than 404ing -- all with zero regressions in the existing native storage test suite.
